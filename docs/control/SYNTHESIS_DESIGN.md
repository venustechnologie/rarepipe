# Synthetic Biological Control Architecture Compiler — design

The control compiler answers *given candidate controls, do they reach the desired state?* This
layer answers the inverse:

```
desired state → required functions → architectures → building blocks → actuators
```

It does not assume the answer must repair the altered gene, restore the original protein, follow a
natural pathway, use a single intervention, or correct every cell. Repair is one family among
several, and the compiler is not permitted to prefer it because it is the obvious one.

The map it produces for the first case is
[`MVA_ARCHITECTURE_MAP.md`](MVA_ARCHITECTURE_MAP.md), generated by
`tools/control/compile_mva_synthesis.py` and checked for staleness by a test.

## Two separations carry the design

**Reason with agents. Prove with code.** Agents imagine architectures, name building blocks, find
compensations and attack weak routes. Only deterministic code decides reachability, safety,
observability, robustness, and whether anything was synthesized at all. The gate — not the
proposer — assigns the epistemic type, and a proposal that states a verdict in any vocabulary the
compiler owns (`ROBUST_CONTROL_CANDIDATE`, `LOGICALLY_SYNTHESIZABLE`, `PHYSICALLY_FEASIBLE`, a
result class) is refused outright.

**Logical synthesizability is not physical feasibility.**

```
logical solution  ⇏  feasible intervention
```

`LOGICALLY_SYNTHESIZABLE` means a composition of declared transformations reaches the target in
the mathematics. `PHYSICALLY_FEASIBLE` means there is evidence those transformations can be
produced in the relevant cells. The second is computed **only** from the components' own
feasibility fields, never from the logical result, and
`SYNTHETIC_ROUTE_FEASIBILITY_UNKNOWN` is a successful output with its blockers named. Collapsing
the two is how an elegant diagram becomes a treatment proposal.

## What a building block is

Not a drug name — what a piece can *do*. A block is stored as a typed transformation of state
(`variable → value`, with direction, scale, cell type, reversibility, validity domain,
uncertainty, provenance and its own feasibility status), so pieces can be composed without ever
consulting a therapeutic indication. Two rules keep it honest:

- **Off-target and safety effects are transformations too.** A component that depletes a
  population declares that as a state transformation, not as a footnote, so the hard safety filter
  sees it. A risk that lives only in prose cannot reject anything.
- **Reversibility must say what reverts.** A block declared reversible states what value its
  variable returns to and what returns it. Without that, releasing it — in a loop, or when asking
  whether the state survives withdrawal — would invent a reversion mechanism the model lacks.

## Composition

A composition is a sequence of steps, each a set of blocks acting together. Expansion turns it
into the control strategy the existing reachability engine already understands, so every guarantee
that engine provides applies unchanged: asynchronous all-interleaving exploration, terminal SCCs
rather than single paths, hard safety filtering, and unknown functions fixed per trajectory. The
synthesis layer adds no reachability semantics — it only decides what to compose.

Three checks belong to the composition itself:

- **Conflicts.** One variable cannot be held at two values; a composition that tries is refused
  rather than resolved by sort order.
- **Preconditions.** A block declaring the states it can act in is checked against the belief at
  the step where it acts, so "works, provided it is applied to a cell already in state X" cannot
  pass as "works".
- **Whether the order matters.** `SEQUENTIAL` is a claim, so it is tested: every permutation and
  the simultaneous collapse are re-run, and the order is called load-bearing only when some
  alternative gives a different verdict. Where it is not load-bearing, the equivalent orderings
  collapse to one representative whose note records how many were evaluated.

**Overrides.** Holding a variable that a relationship already defines is recorded as overriding
that relationship, with its epistemic status. A bypass works precisely by asserting that some
mechanism can supply a value the model attributes elsewhere — that is a requirement of its own, and
overriding an *established* relationship is a larger claim than filling a gap.

**Minimality.** An architecture whose component set strictly contains a reported one with the same
outcome is dropped. Its extra component changes nothing, and listing it would present a free
passenger as load-bearing.

## Feedback

The control compiler's semantics are open-loop on purpose: controls accumulate and are never
released, because releasing one would let a transient push lock in a state nothing maintains.
Feedback needs release, so it is admitted under one condition — a control can only be released if
it declares what its variable returns to.

A policy is `u(t) = π(y(t))`: rules keyed on *measured* variables (a controller keyed on an
unmeasured variable is not a controller) with activate/deactivate actions. The loop is evaluated
as a finite transition system over composite nodes `(plant state, controls held)`; from any node
either the plant takes an asynchronous causal step or the controller fires one applicable rule, and
every interleaving is explored. No sampling interval is invented, because none is grounded — which
also means a loop is only reported as maintaining the target when the unsafe region is
structurally unreachable, never merely unlikely to be raced into.

## The population scale

`∂ρ/∂t = T + R − D + S` is the conceptual specification. The honest finite implementation is a
population variable in the same state space, moved by **named mechanisms**, each of which must
state what produces the differential; "selection" is not an answer. The load-bearing rule
generalises something the control compiler found for one measurement:

> No population-level improvement counts as functional success while an omitted process could
> produce the same observation.

Every population outcome declares the processes that could fake its reading and the observables
that would exclude each. A process the model does not represent has no node to be an ancestor of,
which is exactly why it must be declared rather than derived from the graph. Separately, a target
reached at population scale states in the same breath that **no cell was corrected** — the two can
never be reported as the same event.

## Stability

Reaching a state and holding it are different claims. `x(T) ∈ X_target` says nothing about
`x(t)` for `t > T`.

| Class | Meaning |
|---|---|
| `SELF_STABILIZING_TARGET` | withdraw every control to its declared release value and every attractor is still inside the target |
| `MAINTAINED_TARGET` | the target holds while the controls are held, but not after withdrawal |
| `TRANSIENT_TARGET` | the target is visited but is not where the system settles |
| `UNKNOWN_STABILITY` | the default: any control that does not declare what its variable returns to makes withdrawal unevaluable |

`UNKNOWN_STABILITY` being the default is the point. A model with no time in it cannot support a
claim about durability, and the absence of a decay mechanism is not a maintenance mechanism.

## Robustness

`M` is the set of models still compatible with the evidence, and each expands into one variant per
candidate for each unknown relationship. Robustness is quantified over all of it:
`A` is robust **iff** it reaches the target under every `M_i` and every candidate within each.
`MODEL_DISAGREEMENT` outranks the rest: when evidence-compatible models give different verdicts,
the honest output is the disagreement, never its favourable half.

## Experiments v2

Which single reading eliminates the most candidate architectures. Two kinds:

- **Relationship discriminators** — where architectures disagree because they depend on an unknown
  resolving differently, a measurement whose value sets are disjoint across the candidates
  separates them. Each reading is pre-committed to the architectures it eliminates.
- **Premise tests** — an architecture whose component has no demonstrated implementation rests on
  the premise that the component achieves its declared transformation. The test is the component's
  own target variable; without it, a failed component and a refuted architecture are
  indistinguishable.

Expected information gain is **not** computed: `I(a;A)` needs a probability over the
architectures, and assigning one would put an invented prior at the centre of which experiment gets
run. The criterion is deterministic elimination, named in the report. A discriminator no existing
experiment can read is reported as a gap in the measurement set, not as an experiment.

## Result precedence

Most fundamental limitation first, so the headline never overstates:

1. `SPECIFICATION_INCOMPLETE` — success is not defined, so nothing can be synthesized for it.
2. `ARCHITECTURE_INDETERMINATE` (fail closed) — a relevant variable has no defining relationship,
   the search or an unknown is too broad to enumerate, or no variant is evidence-consistent.
3. `ARCHITECTURE_SYNTHESIZED` — robust, safe, observable, and every component established.
4. `ARCHITECTURE_OBSERVABILITY_INSUFFICIENT` — reaches the target, but the measurements cannot
   distinguish it from a process that looks the same.
5. `SYNTHETIC_ROUTE_FEASIBILITY_UNKNOWN` — reaches the target under every compatible model; what
   is missing is a way to build it.
6. `ARCHITECTURE_MODEL_DISAGREEMENT`.
7. `ARCHITECTURE_INDETERMINATE` — reaches the target somewhere, with blockers named.
8. `NO_ARCHITECTURE_SYNTHESIZED` — a statement about this registry and this model, not about
   biology.

## What is not built

No universal virtual cell. No bespoke differential-equation solver — `INTERVAL` variables are
recognised by the contract and refused by this engine, which is why the scale path is an adapter to
an established solver rather than silent discretisation. No drug recommendation engine, no agent
per gene, no numerical embedding standing in for a biological equation, no dashboard of speculative
probabilities, and no combination searched merely because combinations exist (hence minimality).

## Proof gates and invariants

Twelve gates in `tests/test_synthesis_gates.py` — direct repair, bypass, composition, the unsafe
shortcut and harm appearing downstream of a component, a population solution and its confounded
twin, a load-bearing order, feedback where static control fails, model disagreement, a missing
actuator, MVA alternative-route generation (`tests/test_synthesis_mva.py`), and no invented path.

Eighteen invariants in `tests/test_synthesis_invariants.py`, including the one that matters most
for how this work gets read: **no treatment recommendation can be produced.** The report carries a
fixed statement that cannot be reworded, and a narrow scan refuses advisory phrasing anywhere in
its free text — narrow on purpose, with negative controls proving that ordinary scientific language
("dose-dependent", "the authors recommend caution") does not trip it.

Gates that pass on the first run prove little, so the properties are mutation tested: each one is
broken deliberately and the matching gate must go red. That exercise is what added the
downstream-harm gate — the original safety gate turned out to be satisfied by the initial-state
check alone, leaving the per-successor check untested.
