
# T12 — evaluation runner, generated reports, exports and the submission claim index

You own **`src/rarepipe/stages/network/evaluate.py`** and **`src/rarepipe/stages/network/report.py`**,
plus **`tests/test_network_t12.py`** and an `evaluate` command group appended to `network/cli.py`
(append only).

Read `tools/m5/sim/run.py` and `tools/m5/sim/report.py` first. They already solve most of this
correctly in this repository — provenance capture, two-digest separation, generated prose — and the
mistakes they encode were made here for real. Follow that pattern rather than a fresh design.

## The evaluation runner (`evaluate.py`)

Run the learner from `policy_q.py` and both baselines from `sim/baselines.py` over the world split
from `sim/splits.py`: train on `train_families`, tune on `development_families`, evaluate on
`held_out_families` with epsilon zero. Produce a run record containing:

- the configuration, canonicalised
- master seed and every derived stream key, via `KeyedExogenousRNG`
- code revision **and dirty state**, runtime and dependency versions
- the world split id and its digest
- the policy version and its parameter digest
- every episode's reward breakdown, taken from `RewardScorer.reward_step` — never recomputed here
- the leakage report from `check_split_leakage`

Two separate digests, as in `tools/m5/sim/run.py`:
- `science_digest` — the simulated content only, which must be identical across two fresh-process
  runs of the same configuration (A20);
- `results_digest` — the whole document including provenance, which legitimately differs when the
  code revision differs. Store each digest's coverage definition beside it.

**A20 test:** run the evaluation twice in **separate processes** (`subprocess`, with
`PYTHONHASHSEED` left random) and assert the `science_digest` values are byte-identical while
naming the provenance fields that may differ. A single in-process repeat does not test this — the
seeding bug this rule exists for only appears across processes.

**A19:** assert in a test that the learner and both baselines received the same observation
contract and the same budget, and that the held-out families were never fit on.

## The report (`report.py`)

Generate every number and every sentence from the run record. **Never transcribe a rate, a count or
a digest into prose** — a fabricated digest and a stale stored summary both reached a reviewer in
this project. Each rate is rendered from its `ReportedRate` with numerator, denominator and an
interval appropriate to its sampling unit, or an explicit statement that no interval applies. Any
summary figure is derived at render time; do not store a derived summary and re-render it later.

The report must state, in generated text: what is implemented, what was observed, what is
simulated, what remains proposed, what is unresolved, and the limitations of each. A simulated
improvement is not a clinical benefit and the report must not read as though it were.

## Exports (A24, A28)

An export path that drops any `restricted()` field, every case identifier, exact variant, position,
private path and recipient detail, and refuses to emit restricted text unless a recorded permission
expressly allows it. A contribution's restrictions survive the export, survive routing to another
case, and survive training selection — test all three. Scan the produced export for case-private
terms before writing it, and fail the export rather than warning.

## Submission claim index (A29)

Map each important report claim to its source or software artifact and classify it as exactly one
of `observed`, `implemented`, `simulated`, `proposed`, `unresolved`. The index is generated from
the run record and the repository, not hand-written. A claim with no artifact is `unresolved`, not
`implemented`. An unresolved external milestone (the authentic institutional pilot, T14) stays
visible in the index as pending, with the next authorized action named — do not let a synthetic
fixture mark it complete.

**A22:** a later correction or permission change invalidates affected derivatives and any pending
dependent action. Call `adapter.py` and `RewardScorer.invalidate_family`; do not reimplement
invalidation. Test that a correction arriving after a report was generated marks that report's
affected claims invalid rather than leaving them standing.

## Tests (`tests/test_network_t12.py`)

At minimum the cross-process A20 test, the A19 equivalence test, the three A24 restriction-survival
tests, the A28 export scan, the A29 classification test including the pending external milestone,
and the A22 invalidation test. Run `uv run pytest -q tests/test_network_t12.py` and report the real
exit status — do not pipe pytest through `tail` or `head` and read the pipe's status.
