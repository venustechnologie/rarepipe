## What a view is here

A view is a **pure projection over stored records** returning a typed payload. It takes an event
log / outbox / campaign and returns data; it does not compute science, does not decide, does not
dispatch and does not write. Rendering (CLI text) is a thin layer over the payload, so a test can
assert on the payload rather than on formatting.

A static snapshot is not enough (PRD §15): the operator must be able to drive intake, action
selection and queue management from these payloads, so each view exposes the *actions currently
available* and their preconditions — but performing one goes through the owning module.

## Required views (PRD §15)

| View | Must carry |
|---|---|
| `case_view` | current question, known and unknown premises, latest change, next task, owner, trigger |
| `network_view` | explained candidates; public evidence held apart from confirmed availability/permission |
| `requests_view` | exact draft or sent content, authorization status, task state, next follow-up, stop/pause controls |
| `contribution_review_view` | original permitted content, structured proposal, missing fields, applicability, evidence family, reviewer action |
| `scenarios_view` | selected world assumptions, action trace, resulting decisions, persistent synthetic label |
| `learning_view` | baseline comparisons, reward components, policy version, updates, limitations |
| `audit_export_view` | provenance, supersessions, scoped sharing, plain-language account of actual work |
| `family_summary_view` | what changed, what it means, what remains unresolved, who owns the next step |

## Hard requirements

- **A16 — no hidden truth in a view.** No view may read `world.latent_for_scorer`,
  `LatentScientificTruth`, or any scorer-only bundle. Test this by attacking it: build a world
  whose latent says one thing, render every view, and assert no latent value appears anywhere in
  the payload, including nested dicts, labels, ids and free text. Reuse T08's
  `_assert_no_latent_keys` approach rather than inventing a weaker check.
- **A15 — synthetic stays labelled.** A synthetic scenario or synthetic feedback is labelled
  synthetic in **every** payload that carries it, and the label cannot be dropped by a filter, a
  projection or a summary. A view must never present synthetic material as campaign evidence.
- **A12 — every live waiting task shows an owner and next trigger, or a visible unscheduled
  reason.** `requests_view` must make an unowned or untriggered live task impossible to hide: it
  is surfaced, not omitted.
- **A30 — pause/cancel and handoff.** `requests_view` exposes the stop/pause controls that
  `outbox.stop()` implements and `audit_export_view` shows that the recorded history survives a
  pause, a cancel and a handoff. Call `outbox.stop` / `outbox.handoff` / `outbox.resume`; do not
  reimplement them.
- **Nothing fabricated to fill a screen** (PRD §15). No invented continuous activity, no
  partnership status that no reply established, no efficacy confidence, no clinical lead and no
  family preference that was never recorded. Where there is no record, the view says so explicitly
  — an empty field is a stated unknown, never a blank or a plausible default.
- **Q values are not probabilities.** `learning_view` must refuse to render a Q value as a
  percentage, a probability of biological effect, or a chance that an institution will help.
  Carry the unit and the limitation text with the number.
- **Rates carry counts.** Any rate in any view arrives with its numerator, denominator and an
  interval, or states why no interval applies. Take them from `ReportedRate`; do not recompute.

## Tests (`tests/test_network_t11.py`)

Assert at least: the latent-leak attack above; a synthetic scenario staying labelled through a
summary projection; a live waiting task with no owner being surfaced rather than dropped; the
family summary containing no fabricated clinical lead or partnership status when none is recorded;
a Q value refusing percentage formatting; pause/cancel preserving recorded history. Run
`uv run pytest -q tests/test_network_t11.py` and report the real exit status.
