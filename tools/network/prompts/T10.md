# TASK T10 — Q-learning policy, persistence, masking, shadow mode

Deliverable: `src/rarepipe/stages/network/policy_q.py`. Tests: `tests/test_network_t10.py`.
Acceptance: A17, A18, A19. Depends on T09 (reward, baselines, splits) and T08 (world).

Implement the tabular Q-learner of PRD §13. It is an inspectable engineering MVP, NOT a validated
clinical decision model. Report it as a bounded observation-state policy; make no convergence or
global-optimality claim anywhere in code, docstrings or output.

Update rule: `Q(s,a) ← Q(s,a) + α[r + γ max Q(s',a') − Q(s,a)]`, zero future value at terminal
states, maximization restricted to ELIGIBLE actions. Defaults: alpha 0.1, gamma 0.95, epsilon
linearly 0.2 → 0.05 over training and epsilon 0 for held-out evaluation. These are adjustable
simulator settings, not scientific quantities — label them.

The joint action encodes a micro choice (question / clarification / analysis-feasibility task) and a
macro choice (node / route / follow-up / wait). ONE learner optimizes both. Do not create two
independently learning policies.

Action space: request an existing finding, ask a clarification, verify a capability, verify a
referral, request method feasibility, request a local-analysis proposal, follow up, wait, prepare
scientific review, stop a route, pause. Laboratory execution and patient actions are NOT in the
action space and must be unrepresentable, not merely unused.

Observation-state encoder: question status, missing prerequisites, evidence overlap, node
capability-confirmation states, permissions, requests in flight, elapsed-time bucket, budget
remaining, context compatibility. VERSION every bin and feature. No hidden result labels may enter
the encoder. Keep full event history for audit even though the learner uses compressed features.

Permission and scientific-gate masks apply BEFORE both exploration and exploitation — an ineligible
action must be unreachable by a random draw, not merely unlikely. Log the actual selection
probability at decision time; never reconstruct a propensity afterwards.

Q values estimate simulator utility under the configured reward. They must never be rendered as drug
efficacy probabilities, confidence in a biological claim, or the chance an institution will help.
Enforce this at the reporting boundary.

Shadow mode: for an authentic campaign, the policy stores recommendations ALONGSIDE the actual
authorized actions and never dispatches. A real parameter update requires actual eligible feedback
and an explicit training event — data ingestion alone is not an RL update.

Your tests must assert:
- A17: persisted parameters actually change from the declared reward across a training run; a static
  routing table would fail this test.
- A18: eligibility masks constrain exploration as well as exploitation — run many epsilon-random
  draws and assert no ineligible action is ever selected.
- A19: the learner and both baselines receive the same observations and budget.
- Patient/lab actions cannot be represented in the action space.
- Shadow mode records a recommendation without dispatching.
- A Q value cannot be formatted as a probability of biological or institutional outcome.

  `held_out_families` with epsilon zero. Never fit on the held-out families.
